# Technology Baseline --- v0.3

**Authority:** Approved Reference Architecture v2 technical decisions
that have not been superseded by frozen FRS/Domain/Database artifacts.

These choices are part of the Architecture Freeze Candidate. A
replacement outside an explicitly allowed choice set requires an ADR and
human architecture review.

  ---------------------------------------------------------------------
  Area                               Frozen baseline
  ---------------------------------- ----------------------------------

  Cloud database                     Managed PostgreSQL

  Backend                            Node.js + TypeScript modular
                                     monolith

                                     implementation must use **Kysely

## Selection still allowed inside the baseline

The approved data-access baseline intentionally allows **Kysely or
Drizzle**. The project must choose one before production repository
implementation and record the choice in an ADR. Introducing a different
ORM/query builder is not permitted without a new ADR.

## Non-negotiable implementation implications

-   JavaScript/TypeScript floating-point `number` is not used for domain
    money/cost arithmetic.
-   UUIDv7 is generated by application/client infrastructure, not by
    relying on a PostgreSQL UUIDv7 extension.
-   pg-boss uses PostgreSQL and does not introduce Redis at the Store
    Node.
-   OpenAPI/Zod schemas become the API-contract source for generated
    clients and validation.
-   The custom sync protocol preserves the frozen ownership, inbox
    deduplication, idempotency and outbox rules.
