# v1.2 Persistence Amendment Rules

A COMPLETE ACTIVE Item requires base and sales Item-UoM references; a
purchasable COMPLETE ACTIVE Item also requires a purchase Item-UoM.
Composite FKs guarantee that role references belong to the same Item.
Skeleton records may remain partial until promotion.

`stock_managed` is explicit Item-owned state and is never inferred from
sellable/purchasable.

Repeatable identifier child tables are canonical for new writes. Legacy
single-value identity fields are migration input only and are absent
from the v1.2 new-install DDL.

Posted-document snapshots are immutable historical evidence. Existing
history may be backfilled only from authoritative immutable evidence;
unknown history remains unknown.

Store Node association is derived from
`integration.store_service_instances`, preserving the architecture
boundary.

## Snapshot schema version contract

`snapshot_schema_version` identifies the **canonical immutable snapshot schema that was used at posting time**.

Rules:

1. The Posting Envelope coordinator that owns the posted document also owns the snapshot contract used by that document.
2. Company, Store, Customer and Supplier snapshot JSON must be produced from an explicitly versioned snapshot schema.
3. The snapshot payload and its `snapshot_schema_version` are committed atomically with the posted document, Audit record and Outbox message.
4. A historical snapshot is interpreted using the schema version recorded on that posted document.
5. Historical snapshot JSON must **never** be reinterpreted by applying current master-schema defaults, current master values, current country configuration, or a newer snapshot schema.
6. Later master-data edits or snapshot-schema revisions must not mutate an already-posted snapshot.
7. New snapshot versions must remain readable for historical rendering/reprint/reporting for as long as the corresponding posted documents are retained.
8. Migration/backfill of historical snapshots is permitted only from authoritative immutable evidence. When such evidence is unavailable, the historical value remains unknown rather than being reconstructed from current master data.

This rule applies to every v1.2 posted-document snapshot field, including Company, Store, Customer and Supplier snapshots.
