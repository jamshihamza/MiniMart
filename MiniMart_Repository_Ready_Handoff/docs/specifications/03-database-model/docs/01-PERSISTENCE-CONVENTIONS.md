# Persistence Conventions

## 1. Naming

-   PostgreSQL schemas: lowercase bounded-context names.
-   Tables/columns: `snake_case`.
-   Primary key: `<entity>_id`.
-   Foreign/reference identity: `<referenced_entity>_id`.
-   Boolean: `is_*` only for true binary facts.
-   Timestamps: `*_at`.
-   Business operating date: `business_date`.
-   Human document number: `document_no`; never primary key.
-   Optimistic version: `version`.

## 2. UUIDv7

UUIDv7 is generated by the application before persistence.

Reasons: - globally stable offline identity; - naturally sortable enough
for B-tree locality; - safe creation at multiple counters/store nodes; -
cloud sync does not need ID remapping.

The database validates `NOT NULL` and uniqueness but does not generate
random UUIDs as a fallback.

## 3. Numeric precision

`numeric(24,8)` is the v0.1 storage baseline for money, price, quantity
and cost.

Rules: - application uses exact decimal type; - no
`real`/`double precision` for business values; - currency is stored
beside monetary documents/facts; - final tax/rounding results are stored
explicitly; - zero/negative rules are constrained per table rather than
globally.

## 4. Timestamps

-   `created_at timestamptz NOT NULL`
-   `updated_at timestamptz` on mutable roots
-   `posted_at timestamptz` on posted documents
-   `occurred_at timestamptz` on immutable facts
-   `business_date date` stored separately

Database server time is not a substitute for BusinessDate.

## 5. Version columns

Mutable roots use:

`version bigint NOT NULL DEFAULT 0`

Application update pattern:

`UPDATE ... SET ..., version = version + 1 WHERE id = ? AND version = ?`

Posting paths may additionally lock the row.

## 6. Historical snapshots

Posted document lines store snapshots such as: - item code/name/UoM; -
party name/tax identity where required; - price/tax/discount calculation
outcome; - country-rule-set reference; - currency; - source document
number/reference.

Snapshots are explicit columns for critical searchable/reportable facts.
`jsonb` may hold secondary extension data, not replace the relational
core.

## 7. Status columns

Frozen lifecycle states use CHECK-constrained text where stable.

Open policy outcomes are not encoded as a database enum/default until
approved.

## 8. Deletion

Business masters use deactivation/status, not physical deletion when
referenced historically.

Posted documents/facts are never physically deleted through application
workflows.

Retention/anonymization requiring deletion is governed separately and
must preserve financial/audit integrity.

## 9. Audit columns

Mutable master/root tables generally include: - `created_at` -
`created_by` - `updated_at` - `updated_by` - `version`

Posted facts additionally include `posting_envelope_id` and
source/idempotency identity where relevant.

## 10. JSONB rule

Allowed for: - provider-safe metadata; - country-rule configuration
values; - diagnostic extension metadata; - non-authoritative event
payload.

Not allowed as a substitute for: - line quantity; - money/tax totals; -
stock balance; - WAC; - credit outstanding; - document lifecycle; -
primary business relationships.
